## 2. 下の黒い余白の原因（コードで確定したこと／確かめられていないこと）

- **コードで確定**：画面は 390×844 の論理画面（`.stage`）を拡大縮小して置く（`src/core/stageLayout.ts`）。
  `.stage` は `.viewport`（`src/style.css`）の中にあり、`.viewport` は iPhone のセーフエリア（上の切り欠き・下のホームバー）を**除いた**範囲。
  セーフエリアの帯は `body` の背景色（`--color-bg` #111317：ほぼ黒）がそのまま見える。縦長の画面では `.stage` の高さが伸び、横に広い画面（Safari のアドレスバーありなど）では幅が 480 まで伸びて、それより広い分だけ左右に余白ができる。
- **対戦画面の中**：旧配置も新配置も、論理画面の高さ 844 を全部使っている（3つの画面サイズで実測。下に空きは出ない）。
- **確かめられていない**：動画（V4）が手元にないため、動画の「下の黒い所」がセーフエリアの帯なのか、別の原因なのかは未確認。
  セーフエリアの帯に対戦の背景を伸ばすなら全画面共通の変更（`#app` の背景）になるので、今回は入れていない（提案のみ）。

## 6. フェーズ1の準備：動画 V1（ダンジョン・2.6秒）の所見（2026-10-24 受け取り。まだ何も変えていない）

- 端末は 1180×2556（iPhone 15/16 Pro 相当）。画面いっぱいにダンジョン全体（B1F）が一度に映り、主人公はかなり小さい
- 地図の上に細い黒い帯、地図の下に大きな黒い所。スティックは指を置いた所に出るので、下の真ん中だと「街へ帰る」の階段と重なっていた
- 2.6秒と短いので、歩き方の細かい所（足踏みと移動のずれ等）はこの動画だけでは判断できない
- **コードで確定した原因**：ダンジョンは仮の記号の地図で、1マス 40（`worldScreen.ts` の `TILE`）、人物の高さ 54 に固定。B1F は 12×16 マス＝480×640。
  地図の縦が画面より短いと、カメラは動かず地図を上下の真ん中に置く（`worldScreen.ts` のカメラの `mh <= vh ? (vh - mh) / 2` の所）。動画の上下の黒い所はこの余り。
  街・部屋のように画面に合わせて大きくする処理がダンジョンにはない
- 直し方の見込み：ダンジョンだけ倍率（指示書の候補 1.25・1.5・1.75 倍）を掛けてカメラが追うようにし、撮り比べて決める。階段・敵・出口の位置や当たり判定は変えない

- フレームの落ち方の数値の計測（画面のまねでは引っかかりは見えなかった）
- 縦長でない端末・横持ち

### 2026-10-24 試遊の動画（12:54）で分かったこと：黒い余白の補正は取り消し

- 補正を入れた版では、ゲームが 793pt まで広がったが、**画面の下（約25pt）が切れて「調べる」ボタンの下が欠けた**。
  iPhone がゲームに使わせている範囲そのものが 793pt までで、その下はゲームから描けない場所だった（見込みが外れた）
- そのため `#app` の高さを変える補正（`shortStandaloneHeight`）は取り消した（作業ブランチ。`?qa=1` の数字の表示は残す）
- 残る原因の見込み：ホーム画面から開いたときの上の帯の設定（`index.html` の `apple-mobile-web-app-status-bar-style` が `black-translucent`）と iPhone の組み合わせ。
  `black` などに変えると直る見込みがあるが、iPhone はこの設定をホーム画面に追加したときに覚えるので、**変えたら一度ホーム画面のアイコンを消して追加し直す**必要がある（未実施・ユーザーの判断待ち）
