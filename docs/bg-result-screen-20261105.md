3. **ひと言が無いとき（引き分け）**は、窓を名前だけの高さに縮める（`is-nameonly`）
4. **戻る先の曲**（`tools/e2e/bg_bgm_check.cjs`。結果の曲を「続ける」で止めたあと、戻る先の画面を作って、頼まれている曲を調べた）：

   | 戻る先 | 戻り方 | 鳴る曲 |
   | --- | --- | --- |
   | 街（ピート・イベントの対戦・導入の試験のあと） | 歩く画面を作り直す（`ctx.reset('world')`） | 街の曲（town） |
   | 練習場（練習試合のあと） | 同じ | 練習場の曲（practice） |
   | 家・研究所 など部屋 | 同じ | その部屋の曲（home・lab） |
   | ダンジョン（ランダム生成：機械の塔・風の渓谷で確かめた） | ダンジョンの画面を作り直す（`ctx.reset('dungeonRun')`） | そのダンジョンの曲（dungeonMachine・dungeonWind） |
   | 前の手作りのダンジョンの地図 | 歩く画面を作り直す | そのダンジョンの曲（歩く画面の DUNGEON_BGM。表で確かめた） |
   | 大会：次の試合の前・大会の終わり | 大会の画面に戻る（`ctx.back('tournament')`。画面は作り直される） | 大会の曲（tournament）。次の試合は対戦の画面が大会の対戦の曲 |

   - 画面を移るときは、どの画面も作り直され、作るときに自分の曲を頼むので、鳴らない所は無かった
   - 直したこと：結果の曲を 0.3 秒で小さくしている間に次の曲が鳴り始めて重なっていたので、**止め終わってから次の曲を鳴らす**ようにした（`bgm.ts` の `#quietUntil`）
- あわせて直したこと
  - 結果画面は描き直すたびに作り直されるので、判子・主人公の出てくる動きが描き直しのたびにやり直しになっていた → 出し始めからの時間（`--result-t`）だけ動きを先へ進めて続けるようにした
  - ステラのひと言で「、」が行の頭に来ていた → 文節の区切り（phraseText）で、句読点・閉じかっこで始まる文節を前につなげる。窓の内側の余白も少し減らした
