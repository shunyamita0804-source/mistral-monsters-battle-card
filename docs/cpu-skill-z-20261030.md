## A. CPU の腕前（C 下手・B ふつう・A 上手）

- 今の考え方（normal・aggressive など）は「構え」として残し、別に「腕前」（`OpponentDefinition.skill`。無ければ B）を足した。`chooseAction(state, side, style, skill)`
- ふるまいの数字は `src/game/battle/ai.ts` の `CPU_SKILL` に1か所でまとめた（仮）

| | C 下手 | B ふつう | A 上手 |
| --- | --- | --- | --- |
| 倒せる相手がいるとき | 50% で見のがす | 20% で見のがす | 必ず倒す。倒しすぎない技（威力−残りライフが小さい・安い順） |
| 倒せないときの狙い | ばらばら | ばらばら | いちばん危ない相手（技の最大ダメージ÷残りライフ） |
| 攻撃するか | 攻撃できる手番の 15% で見送る（記録「〇〇は迷っている…」） | いつも | いつも |
| 技の選び方 | 30% で使える技からばらばら | 強い技から | 強い技から。倒せない手番に、弱い攻撃（2以下）を使うと次の手番に大技（3以上）が払えなくなるなら、その攻撃をやめる |
| 守るか | 守れるのに 40% で守らない（記録「〇〇は守りそこねた！」） | 3以上か倒されそうなとき回避、ほかは防御 | B と同じ（1〜2 には回避を使わない） |
| マナ化で残す守り | 0枚。30% の手番で守りを先にマナにする | 1枚 | 2枚。相手の技の種類に合う守りを先に。守りの分のマナが足りなくなるなら攻撃の札も残さない |

- 「ばらばら」は対戦の seed・手番・記録の行数から決まる（`cpuRoll`。同じ場面では同じ値）
- **「ライフの少ない相手から狙う」はやめた**。hunter の構えは「最大ライフの少ないモンスターから」だけ。投石（攻撃のあと）の狙いも攻撃と同じにした（Y では「いちばんライフの少ない相手」だった）
- 構えは腕前より優先（aggressive は A でも倒されそうなときしか守らない・守りを残さない。guard は守りを2枚残す）
- 記録の文は `battle.log.hesitate`・`battle.log.misguard`（英語は仮訳）。「〇〇」はその側の名前（大会の相手の名前など）
