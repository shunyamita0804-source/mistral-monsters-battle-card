ミスモンBC｜技カード・サポートカードの新しい形（2026-10-28 進行チャット）

■ 目的
ユーザー「技カードの情報量が多く頭に入りづらい。必要マナとダメージ、そしてイラストがすぐ伝わることが一番大事」。
今の枠（v5・6つの札）をやめて、「平らな名前の帯＋大きな絵の窓」だけの枠にし、
マナ・分類の印・ダメージ・名前・効果の説明は、ゲームのコードで絵の上に重ねる。
ユーザーが選んだ見本：ref/approved_layout_mock.png の「案」。新しい枠で組んだ見本：ref/mock_new_frame.png。

技カードはすべて src/ui/components/skillCard.ts の1つの部品で描いているので、そこを作り直せば
図鑑・デッキ編集・ショップ・ガチャ・詳しい表示・対戦（手札・大きなカード・守備・演出）すべてに効く。
モンスターカード（場のバトル用カード）は今回変えない。

■ 入っているもの
- frames/frame_normal_simple.png（1012×1528）：大きなカードの枠。銀＋金のふち＋平らな名前の帯＋透明の窓
- frames/frame_hand_simple.png（832×840）：手札の枠。名前の帯なし
  ※ デザイン担当の絵は、手札用の外側の下と右に白い帯（約7px・不透明）が残っていたので、進行が透明にした（それ以外は無改変）。
    デザイン担当から届いたままの絵は frames/original/ に。原本としてそのまま保管してください
- ref/layout_positions.png：下の「位置」を枠の上に描いた図（左：大きなカード、右：手札。赤い縦線＝手札の重なりで見える左35%）
- ref/frame_colors_lineup.png：各モンスターの色に塗った見本
- tools/tint_reference.py：進行が色を塗るのに使った式（参考。今の skillcard_v5_monster_color.py の ramp_of と同じ考え）

■ 1. 枠の絵
- 2つの枠は、今の LAYOUT（normal 253×382・hand 208×210）のちょうど4倍の大きさ。LAYOUT の数字（縦横比）はそのまま使える
- 原本は design-parts/ に無改変で保管。ゲーム用は今と同じく LAYOUT の2倍の webp（506×764・416×420）にする（iPhone でぼやけないため）
- 色：銀の所をモンスターの色に塗る（金のふちは金のまま・透明はそのまま）。
  金の見分け：R−B が 40 より大きい画素。それ以外の見えている画素を、明るさに合わせて「暗（色の45%）→色→明（白へ7割）」のグラデーションに置きかえる
- サポートカードは銀のまま（塗らない）
- 色の表（いまの tools/art/skillcard_v3_build.py の MONSTER_COLORS と、バトル用カードの枠の色）：
  soramo #E4D2AC／gauul #E68A46／lazuck #844DC5／nobiton #FFD400（今は技カードに専用の色が無く分類の色。新しい形ではバトル用カードの枠と同じ黄色にする）／
  myurol #84E5FA／kalshell #DFF2F6／pukarim #A8DCC4（確認用の画面だけ）
  仮のモンスター（仮ジオル・仮フルーネ・ほか仮のモンスター）は cards.ts の color を使う
- 新しい形では、枠は「モンスターごとに1枚」（分類ごとの色の枠は使わない。分類は印で見せる）。
  frame_{normal,hand}_{モンスター}.webp と frame_{normal,hand}_support.webp。
  **サポート以外のカードに銀の枠が出ないこと**（色の表に無いモンスターが銀になるとサポートと見分けられない）
- 作る道具は新しく足してよい（例：tools/art/skillcard_simple_build.py）。npm run art:skillframes をそれに切りかえる。
  古い v5 の枠・マナの玉の絵（mana_N.png）は使わなくなる。消すかどうかは任せる（ほかで使っていないかは確かめて）

■ 3. 重ねるもの（重ね順：絵 → 枠 → 印・数字・文字）
- 絵：窓いっぱいに広げる（縦横比を保って、はみ出した所を切る＝cover。真ん中合わせ）。
  今の「全体を入れて、すき間をぼかした絵で埋める」はやめる。窓の角の丸みは枠が隠す
  技の絵は 827×937。大きなカードでは左右が約1割ずつ、手札では上下が約6%ずつ切れる。
  今ある6体の技の絵で、顔・技の見せ場が切れてしまう絵があれば、番号を一覧にして報告（直し方は進行が決める）
- マナの丸：平らな紺 #1B3252 の丸に、細い金のふち（#F0D78C）、白い太い数字（丸の直径の約7割の大きさ）。つや・影はつけない。
  数字の入った玉の絵（mana_N.png）は使わない
- 分類の印：今の icon_{分類}.png（74px。色つきの札：ちから＝赤い拳・かしこさ＝緑の本・防御＝青い盾・回避＝橙の羽・特殊＝紫の星）をそのまま縮めて置く。サポートは印なし
- ダメージの四角：ほぼ黒（#1E1612 を 9割の濃さ）。右上の角だけ丸く（左と下は窓の角にそろう）。中は今と同じ決まり：
  攻撃＝大きな数字だけ（「ダメージ」の字は出さない）／防御＝盾と軽減値（盾 -3）／回避＝「回避」／特殊＝「効果」／サポート＝区分（サポート・全体）。
  数字の大きさは今と同じ（normal 21cqw・hand 22cqw）を上限に、四角に収まるよう今の fitValueFont で
- 名前：白い太い字に、濃い縁取り（どの色の帯でも読めるように。ソラモのクリーム・カルシェルの白っぽい青・ノビトンの黄色でも）。名前の札（箱）はない
- 効果の帯（大きなカードだけ）：ほぼ不透明のクリーム色（#FAF3E1 を 9割）・角を丸く・濃い茶の字。絵の上に重ねる（絵を短くしない）
  - 出す技：防御・回避・特殊・サポートは、今の説明の文（どの技に効くかが要るので）
  - 攻撃技は、追加の効果があるときだけ、その部分だけ（例：「回避されない」「ほっぺにためていると回避されない」）。
    「相手1体に2ダメージ」のような数字の言い直しだけの文は出さない＝ふつうの攻撃技は帯なし
  - 長い文は今の fitText と同じく小さくして2行まで
- 手札の印（使えない＝灰色にくもらせる・選んだ＝持ち上げて金の光・マナにする＝水色の光）は今のまま効くように

■ 4. 確認（画面写真 390×844 と 375×667）
- 大きなカード（手札のカードをタップしたとき）を、ふつうの攻撃・効果のある攻撃・防御・回避・特殊・サポートで1枚ずつ
- 手札に5枚以上ある対戦の画面（重なっていても、マナ・印・ダメージが見えるか）
- 図鑑・デッキ編集・ガチャの結果・ショップの画面で、カードが崩れていないか
- カルシェルの技カードとサポートカードを並べたところ（カルシェルの色は白っぽいので、銀のサポートと見分けがつくか）
- 6体それぞれの技カードを1枚ずつ（色と名前の読みやすさ）
- テストを直して、すべて通す
