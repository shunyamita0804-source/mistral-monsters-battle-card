【題名】ミストラルモンスターズ バトルカード｜カードバトラー管理局 v02 素材の本編組み込み・限定検証

【添付要否】必須

【必要添付】ユーザーから別途直接送付する「カードバトラー管理局_デザイン納品_v02.zip」1点。画像・参考プレビュー・原本・説明書はすべてそのZIP内です。本指示書ZIPには素材を重複同梱しません。

【本文】
目的：受領した「カードバトラー管理局」の正式デザイン候補を、現在の『ミストラルモンスターズ バトルカード』の街に組み込み、建物への入退室、受付での会話、歩行・衝突・前後関係をiPhone縦画面向けに成立させてください。今回は施設の見た目と基本的な利用導線の実装です。未決定のカード制度や報酬を勝手に設計・正式化しないでください。

■対象・作業前の確認
・作業対象は shunyamita0804-source/mistral-monsters-battle-card のみ。育成ゲーム本編 mystic-monsters は変更禁止です。
・開始時に現在のmainとSHA、既存作業ブランチ、CLAUDE.md・docs/handoff.mdを確認し、現在の実装を基準に作業してください。本指示作成時のmain最新検索は b2bbf598（2026-10-27）でしたが、このSHAに固定せず着手時の最新を優先してください。
・必要な現行箇所だけ確認してください：src/data/maps.ts、src/data/worldArt.generated.ts、src/ui/screens/worldScreen.ts、tools/design/seimon_world_build.py、現行街の配置資料、現在のショップ自動ドア、既存NPC、会話/i18n/セーブ実装。無関係なファイルの一斉調査・全E2Eは不要です。
・納品ZIP内「00_最初に読む_UTF8.txt」「docs/LAYOUT_SPEC_UTF8.txt」「docs/asset_manifest.json」「docs/素材出典と流用確認_UTF8.txt」「docs/デザイン受入確認表_UTF8.txt」を必ず確認。ZIPの index.html は素材確認用ページで、ゲーム本体の index.html を置き換えるものではありません。
・新規素材は原本を追跡できる形で保存。previews/は比較検収用であり、本番の部屋背景へ1枚絵として焼き込まないでください。既存正式素材の無関係な修正・削除は禁止。

■1. 街への施設追加
・施設の日本語名称は必ず「カードバトラー管理局」。従来の大会会場の受付、管理局、新しい受付の用途を混同しないでください。
・既存の町の建物・噴水・通路・採用済みの絵を保持し、実際の町マップの空き領域を測って、自然に歩いて入れる位置・縮尺を検討してください。納品ZIPの previews/TOWN_PLACEMENT_STUDY.png は仮配置であり本番座標ではありません。既存建物の上に無理に重ねないこと。
・現在の32pxグリッド、衝突マスク、建物の高さと入口、歩行速度・4方向移動を優先して実寸に変換する。納品PNGの1536×1024は画像座標であって世界座標ではありません。無断で街全体のスケールや地形を作り直さない。
・良好な候補地がなく既存の承認済み街配置の変更が避けられない場合は、強行せず、候補位置・必要変更・見た目比較を示して「配置のみ承認待ち」としてください。安全な空地があれば暫定の実装候補として配置し、正確な座標を報告してください。
・施設の表示名は現行i18nの仕組みで日本語・英語双方に対応。英語の正式名称が未決なら仮訳と明記して実装し、正式決定と扱わない。

■2. 外観と自動ドア
・assets/EXTERIOR_BASE.png、EXTERIOR_DOOR_INSIDE.png、EXTERIOR_DOOR_LEFT.png、EXTERIOR_DOOR_RIGHT.pngを同じ1536×1024の原点で組み立てる。EXTERIOR.pngは閉状態の照合用です。
・ドアは左右2枚が横へスライドする構成。既存カードショップの自動ドア実装・SEをできるだけ再利用し、同じ仕組みを二重実装しない。納品資料の左-116／右+116（半開は±58）、開口部クリップ（x=652〜883、上端曲線y=547+33*((x-768)/116)^2、y<858）は原画像座標の参考であり、画面上に変換する。
・扉を開いたとき、ドアパネルが外にはみ出さず壁側へ隠れる。EXTERIOR_DOOR_INSIDEは固定し、EXTERIOR_BASEは前面。閉・半開・全開を納品プレビューと比較。
・入口のタップ/接近による開閉、歩行可能な入口判定、室内への遷移、退出後の町復帰位置を整合させ、ドアに衝突して入れない・入口でハマる・画面切替を繰り返す等を防ぐ。

■3. 内装と入口ドア
・ROOM_SHELL.png（床・壁）、BACK_SHELVES.png（棚）、COUNTER.png（カウンター）、INTERIOR_DOOR_FRAME.png、INTERIOR_DOOR_LEFT.png、INTERIOR_DOOR_RIGHT.pngを個別レイヤーで使い、画像の原点を統一。家具だけの自動トリミングで位置がずれることを禁止。
・納品プレビューは参照のみ。実ゲームの画面縦横比・歩行グリッドへ換算し、移動する主人公と固定家具を奥行き順で描く。
・内装の歩行領域・家具の床面衝突・立ち位置はdocs/LAYOUT_SPEC_UTF8.txtの提案値を参考に、ゲーム内グリッドへ適合させる。入口→カウンター正面→退出が歩いて到達できること。カウンター越え、壁抜け、戸枠へのめり込み不可。
・カウンターの後ろに受付NPCを立たせ、上半身が見え、下半身がカウンターに自然に隠れる描画順にする。主人公はカウンターの手前、案内役（幼馴染）が同行する既存シーンでは主人公と同じ場所に重ならないこと。
・内装ドアも左右スライド可能な部品として使用。納品資料の開口部x=584〜956、y=720〜954／全開±188（半開±94）は原画像座標の参考。入室時・退出時に扉の重なりや閉じ込めがないこと。
・過去のショップで報告されている「退出時に一瞬主人公の頭が戸枠に隠れる」問題を管理局で再発させないよう、出入りアニメ中の重なり順と足元判定を確認。既存ショップを無関係に修正しない。

■4. 受付NPC・会話・案内UI
・reuse_candidates/の受付立ち絵と会話顔は「流用候補」で、新規正式キャラクターではありません。まず既存ゲーム側の正式受付（大会会場など）とファイルの関係を照合。管理局専用の新しい受付の原画は本ZIPに含まれていないため、今回勝手に新キャラを生成しないでください。
・新しい正式受付素材が未納品なら、既存立ち絵・顔の流用は暫定扱いとし、画像差し替えが簡単な参照方式にする。受付は固定配置でよく、歩行アニメの未完成候補は使わない。大会会場の既存受付を置き換えない。
・受付との会話は既存の会話UI、タップ/調べる操作、日英のi18nを使う。キャラクターのポーズ・顔の破綻、カウンター越しの会話不可を避ける。
・既存の導入イベントに管理局への案内・登録・パック受領が「承認済み仕様としてすでにある」場合だけ、その既存仕様に接続してください。今回の素材だけから新しい資格制度、カード配布、スターターパック3択、回数・枚数・確率、導入台詞、報酬やセーブフラグを創作しないでください。
・仕組みが存在しないときは「施設に出入りして受付と話せる」範囲に留め、未実装の機能は未決の案内に留める。仮の報酬を付与しない。必要なら現在の既存の仮会話1行程度で止める。
・assets/GUIDE_POINTER_REUSED.pngは案内イベントの時だけ任意利用。常時点滅させない。ユーザーが正式採用していない表示を勝手に増やさない。

■5. 検証・成果報告
・新しい建物に町から徒歩で接近→ドアが開く→管理局に入る→カウンターへ歩く→受付に話す→入口から町に戻る、を1連続操作として確認。4方向移動、人物/家具の前後関係、衝突、戸枠、扉のアニメーション、タップと画面遷移を検査。
・390×844（スマホ縦）の実ブラウザで、町の建物周辺・内装の入口・受付・ドア開閉をスクリーンショットで報告。可能なら他の主要幅も最低限確認。iPhone実機合格とは書かず「ブラウザで確認済み／iPhone未確認」を区別。
・既存のショップ・大会会場・家の出入口が壊れていないことを関連テストで確認。npm run check（現行手順）と今回関連の実ブラウザ確認のみ。不要な長時間全E2Eや他システムの再設計はしない。
・セーブを変える場合は従来のセーブを壊さず移行処理・限定テストを行う。不要ならSAVE_VERSIONを変更しない。
・作業ブランチで実装し、変更ファイル・テスト結果・現行mainとの差分・素材出典・公開予定を報告する。main統合およびGitHub Pages公開はユーザーの明示承認後だけ実施してください。force push禁止。
・最低限の報告項目：①配置した場所（地図上で説明）②外/内ドアの動作③NPCの流用/未確定状態④受付で今できることと未実装のこと⑤画面比較・動線QA⑥npm run check結果⑦ブランチとSHA⑧iPhone実機の未検証事項。
・既存の正式採用済み素材・カードショップ・大会/バトル・ガチャの演出を作り直さない。今回の作業で勝手に別の開発依頼へ着手しない。
