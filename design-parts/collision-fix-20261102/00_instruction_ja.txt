■依頼の対象・最重要条件
2026-11-02のiPhone実機試遊で判明した、街と建物内の移動・当たり判定の不具合だけを調査・修正してください。加えてガレスとの正対配置とミレイユの暗さを修正してください。ユーザーの実機撮影3枚・録画4本が一次資料です。最初に実物を再生・確認してください。

前便で送信済みの「初期3ブースター144枚／LIFE修正統合依頼」とは別案件です。混ぜて改修しないこと。既存の正式な街・部屋・家具・人物・会話・導入の仕様を保護。全体のリデザインは禁止。新しい画像生成依頼は不要。原画の無断改変・ゲームバランス・ブースター・技・LIFE・バトルエンジン・ガチャ・音源等は対象外。

作業開始前にリポジトリ shunyamita0804-source/mistral-monsters-battle-card の最新mainのコミットSHA・進行中ブランチ/PRを確認し、すでにある作業と衝突しない限定ブランチで進めてください。古いSHAへの巻き戻し禁止。ユーザーによるmain統合・公開承認なし。今回の到達点はブランチ実装・必要な限定テスト・差分付き報告・PR作成まで。もし先行依頼が編集中なら同じファイルの競合を報告し、独断で競合を統合しない。

■症状（ユーザーからの直接報告：優先順位）
P0-1　街：管理局の入口や周囲の建物判定が厳しく、自然に入口へ入れない。建物外周・入口の開口幅・足元が絵と一致するように調整。
P0-2　管理局室内：掲示板へ行けない。室内の左側の掲示板（bureau-notice-board / NOTICE_BOARD）へ実際に到達して「調べる／掲示板」の内容を開けること。掲示板の絵・調べる対象・手前の床・長いす等の間に立入禁止マスが残っていないか確かめる。左から／手前から／右から、自然な接近方法のうち少なくとも明確な1経路を確保。
P0-3　街：カードショップの入口が狭く判定が厳しい。見た目のドア開口を正しく入れるように。入口へ正面から近づいて自然に入店、退店、再入店ができること。
P0-4　研究所室内：カウンター正面から右へ進めない。動画を参照。カウンター・机・家具の矩形判定が実際より広すぎないか、NPC近接禁止、左右通路幅、床判定を分離して確認。研究所の右側の解析台などへ歩行できること。
P0-5　大会会場の建物外：階段・左右の柱・正面入口の実際の開口に対して衝突判定がずれている。見た目の階段から登れて、入口を利用でき、階段脇の建物外形は通り抜けないこと。
P0-6　大会会場の入口／室内：建物正面のワープ開始位置と室内スポーン・出口がつながり、受付や会場内の必要な通路を移動できること。入口で壁や飾りに不可視の障害物がないこと。
P0-7　全街エリア／全建物室内：歩ける芝生・石畳・床・家具の脇が誤って不可、壁・棚・机・カウンターなどの実体がある部分は適切に不可。見た目の構造と足元の歩行可能領域が整合していること。すべての入り口、室内出口、階段、掲示板／受付／操作対象への経路を再点検。
P1-1　カード練習場：チュートリアルでガレスと主人公が『正対して向かい合う』配置へ修正。現在はガレスの横に主人公が来て横向きで会話してしまう。ガレスの正面（手前）で、主人公が上向き／ガレスが下向きになる自然な位置を優先。顔や体の重なり、机への埋まり込み、ミレイユとの重なりは禁止。正面の立ち位置が塞がる場合は、歩ける実際の床内で安全な正面地点を確保。導入の自動歩行・会話・バトル開始・負けて再挑戦・再開・試験後も成立すること。
P1-2　案内役ミレイユ：街や練習場で、背景と比較して人物が暗く沈んでいる。参照画像と録画で確認し、ミレイユの色・明るさのみを自然に補正。衣装・髪・肌色・輪郭・透明部分・アニメーションコマ・大きさは変更しない。周囲の背景や全人物を一律に明るくしない。既存アセット側の影・二重暗色オーバーレイ・CSSフィルタ・描画スタックによる暗さを先に調べ、過剰露光や白飛びを避ける。室内と屋外の両方で確認。

■重要な設計原則：『判定を緩める』の意味
『全てのマスを歩ける』ことではありません。人物の足元を基準に、現物の建物や家具の地面に接した実体部分だけを通行不可とし、絵の透過余白・張り出した屋根・看板・木の枝・家具の上部・装飾の空白・床の絵などを過大にふさいでいる箇所を直してください。建物の輪郭に沿った開口幅・隅の形状・実際の足場と判定が一致するよう、必要な部分を切り分けてください。
・プレイヤーの当たり判定は全身や画像矩形ではなく足元を基準にする（既存の方式を踏襲）。通路の1マス分の見た目だけで安全とは決めつけない。隣のNPC・家具への視覚上の食い込みも点検。
・屋根や家具の上端など「人物を前に描く／奥に描く」だけの部分は、通行不可マスと切り離す。遮蔽や重なり順は正常維持。
・ワープ（出入口）と歩行不可マスが同じ位置に重なっていないか、玄関直前から開口部まで連続した通路があるか確認。ワープ矩形だけ無秩序に広げない。
・NPCを通り抜けて解決しない。室内の狭い通路ではNPC_SPACE等の一律な周囲拡張で道路がふさがっていないか、歩行と会話が両立する対象別の調整を行う。
・一律で isBlocked() を緩める、TileInfo.solid を全解除、隣接判定をグローバルで無効化する、壁抜けを許すといった対処は禁止。
・原画・建物位置・UIや演出を変えず、現行のマップ生成設計図の判定・入口・配置・インタラクション定義を必要最小限で修正。

■具体的な合格条件（重点）
1) 「練習場」ガレスと主人公が上下に正対し、双方の体が重ならず、ミレイユの表示も暗くない。試験開始・再挑戦・再開で崩れない。
2) 「管理局」玄関を正面から入れる。掲示板の前の実際の床へ到達し、掲示板を開ける。受付・出口も同様に到達できる。
3) 「ショップ」外からドア中央へ移動→入店→店内移動→出口から退店が毎回できる。ドアと家具の見た目に対する通行判定が一致。
4) 「研究所」カウンター前から右側の通路を通れる。机／解析台／図鑑等の必要対象へ到達できる。家具にはめり込まない。
5) 「大会会場の外」階段から玄関まで歩ける。柱／壁／建物外周へはめり込まない。扉を通ると正常に室内へ。
6) 「大会会場室内」入口から受付・会場内・出口へ詰まらず移動できる。対戦表にアクセスできる。外と室内を往復できる。
7) 「他の街の入口と室内」主要建物の出入口・調べる対象が見た目の開口部と一致して使用でき、外周の壁抜けなし。
8) 既存のNPC会話、オート歩行、クリック／調べる、チュートリアル、カメラ、セーブ位置、復帰、アニメ・入口ワープの挙動が壊れていない。

■限定検証のやり方
A. QAヒットマスク (?qa=1&hit=1) を使って、実機参考映像の詰まり箇所と赤い禁止範囲を重ねて目視確認。ビフォー/アフター差が分かる画像を可能な範囲で保存。数字でなく現物を優先。
B. 地図定義を使う純粋関数の限定テストで、重要地点の通行可否、spawnから各ワープ／掲示板／研究所右通路への到達、壁の不可侵、ショップ往復・大会会場往復、NPCとの必要な離隔、マップ出口の整合性を確認。
C. ブラウザで重点地点の移動・反応を確認できる場合、実際に発火したwarp／noticeBoardアクションまで確かめる。単に「マップ上で到達可能」だけで掲示板の成功扱いにしない。
D. npm run typecheck、対象テストに限定した vitest、必要なら npm run build を実行。不要な全E2E、全対戦シミュレーション、大量回数のバトルテストは実行しない。
E. iPhone Safari実機の最終合格はユーザーが行う。Claudeはシミュレータ／コード確認を『iPhone実機合格』と報告しない。
