【Claudeへの統合実装依頼｜3箱切り出し＋ブースターパック選択イベント＋カードショップ対応】
作品：ミストラルモンスターズ バトルカード
施設：カードバトラー管理局
対象：教習所の実技試験合格後のブースター3択イベント、および選択しなかったパックの店頭販売

■この指示が最新版です
本指示は、以前送付した「ブースターパック2回タップ選択イベント」の追加・統合版です。同じ処理を二重実装せず、今回の仕様に置き換えてください。既存導入イベントV2・デッキ・他のゲーム機能を壊さないでください。まず既存実装を確認し、必要差分だけ専用ブランチで修正してください。ユーザー承認前にmainへ統合・公開しないでください。

■添付素材・最優先制約
添付：01_添付デザイン/3箱集合_正式デザイン_原本.jpeg（1536×768px、横並び3箱、白い背景を含む）。これはユーザーが完成・採用した3種類の箱デザインです。
・箱のキャラ・ロゴ・文字・装飾・色・立体的な箱の形は描き直し禁止。
・画像処理で原画を切り出し、ゲーム表示用の個別PNGを3枚作成してください。デザイン生成AIによる再生成は禁止。
・原画像JPEGをアーカイブ保存し、出力はPNG。PNG化は画素が自動的に高解像度化するわけではないので、無理な拡大・AIアップスケーリングをしないこと。
・ゲームは2.5D表現だが、箱のデザインはこの2Dイラストのまま使用する。

■1. 切り出し指示【必須・今回追加】
横並びの箱を左・中央・右の順にそれぞれ1箱ずつ切り出してください。個別画像は箱の正面・上面・側面・四隅・ロゴ・下部商品名が一切切れないようにすること。
原本は1536×768pxで、3箱がほぼ等間隔に配置されています。切り出し範囲の初期案は、左 x=0〜511、中央 x=512〜1023、右 x=1024〜1535（y=0〜767）です。ただし、箱の外形を実画像で確認して各領域の余白を微調整してください。機械的な3等分で箱を欠けさせないこと。
保存名と対応（固定）：
  左  booster_tabidachi.png ＝ 旅立ちのきらめき ＝ booster-1
  中央 booster_rekka.png   ＝ 烈火の猛攻       ＝ booster-2
  右  booster_soukai.png  ＝ 蒼海の守り       ＝ booster-3
画像の周囲の白背景は、品質を保って除去できるならRGBA完全透過にしてください。JPEG由来の白フチ・色にじみ・箱の縁の穴が出るなら無理な透過をせず、白背景のままPNG化した暫定実装でも構いません。その場合は「背景透過未了」と明記し、切り出し済み3枚は差し替え可能にしてください。
色・線・箱の面の陰影は変更しないこと。背景だけを処理し、箱内部にある白や淡い色の装飾を誤って透明にしないこと。
3枚を同じ表示スケールに揃える（素材の縦横比は維持）。比較一覧画像を添えて、各箱のロゴ・商品名・上面・左右側面が欠けないことを確認してください。画像原本・個別PNG・比較画像を成果物として保存し、画像差し替えの参照先をコードに明記してください。

■2. パック名・表示順・掲載モンスター（確定）
左：booster-1「旅立ちのきらめき」／バランス／ソラモ・ガウル・ミュロル
中央：booster-2「烈火の猛攻」／攻撃／ガウル・ラズック・ノビトン
右：booster-3「蒼海の守り」／防御／カルシェル・ミュロル・ノビトン
3種類は最初に選んだ「初期デッキ」とは別の選択です。初期デッキが何型でも、管理局で3箱すべて選べること。
商品名は正式デザイン画像に合わせる。文字データはi18nで管理し、箱の正式デザインそのものは改変しない。

■3. 管理局での選択操作（最重要）
受付の既存セリフの後、iPhone縦画面で3箱を横並びにした選択画面を出す。
初期状態：選択なし、指アイコンなし、受取なし。下部に「気になる箱をタップしてね」程度の短い案内。
1回目：箱AをタップするとAが選択され、Aの近くに指アイコンを表示。幼馴染（neighbor_guide）がAの特徴を一言説明する。仮選択ではパックを受け取らない。
2回目：同じAを改めてタップすると、その操作だけでAに確定。追加の「確認／決定／選び直す」モーダルは出さない。
選び直し：Aを1回タップした後、Bを押したらBの1回目として選択と説明を更新する。Bをさらにタップして初めてBが確定。A→B→Cでも確定しない。
確定したらボタンを無効化して一度だけ受取処理を行い、既存の受付のお礼→管理局から退場→幼馴染によるダンジョン・公式戦・ランク戦の案内→自由行動へ接続する。
選択画面でタップできるのは箱のタッチ領域全体。軽い上下移動や縁取り程度の選択演出は可。指は必ず1か所だけ。指やセリフがモンスターの顔・ロゴ・パック名を覆わないようにする。
幼馴染の説明は3箱が見える画面の一部に出す。会話UIをフルスクリーンで覆ったり、説明モーダルがタップを遮ったりしないこと。既存の表情絵を流用し、別の人物にはしないこと。
高速連打による誤確定を防ぐため、初回選択説明が一度視認できる状態になってから2回目の同一箱タップを受け付ける。単純なダブルクリックを「確認操作」と誤認しないこと。ゲーム表示の反応が鈍くならない範囲の入力抑止を設けること。

■4. 幼馴染の正式な短い説明文
旅立ちのきらめき：
「これは『旅立ちのきらめき』！ ソラモたちのパックで、バランスよく戦いたい人におすすめだよ！」
烈火の猛攻：
「これは『烈火の猛攻』！ ガウルたちのパックで、どんどん攻めたい人にぴったりだよ！」
蒼海の守り：
「これは『蒼海の守り』！ カルシェルたちのパックで、守りを大切にしたい人におすすめだよ！」
補助説明：「同じ箱をもう一度タップすると決定します。」
これらは商品イメージの案内です。特定カードの封入保証・排出確率を意味しません。セリフから排出仕様を創作しないでください。

■5. データ・受取処理
現行mainの関連コードを確認してください。直近確認時点：
・src/data/introV2.ts に BOOSTERS（booster-1/2/3）がある。
・src/ui/screens/worldScreen.ts の #choosePack() は箱を押すと #confirmPack() の別確認モーダルへ進む実装。これを1画面2タップに変更する。
・src/game/story/introV2.ts の claimBooster()・grantPendingBooster()・boosterClaimed・boosterGranted・selectedBoosterKey・boosterClaimId・processedTransactions で1回受取と再開処理を扱っている。既存の安全設計を維持する。
・src/i18n/messages/introV2.ts に正式名と上記台詞、1回目／2回目の案内を登録する。
・必要なCSS等は最小限の変更とする。
試験合格前に管理局パック選択へ進めない。受取済みセーブの再開時に選択画面へ戻らない。選択途中のアプリ終了→再開では「未確定」で3択を表示する。二重配布・二重計上禁止。
パックの封入カード・枚数・排出率について、最新のユーザー承認済み正式資料と現在のデータを照合し、正式情報がコード上にない場合は未確定のままとする。箱に描かれたモンスターから中身を推測しない。既存がcards:nullの場合は、勝手なカードを入れず選択記録のみ・正式データ到着後1回配布できる状態を保ち、不足を報告する。「中身は決まったはず」だけで値を捏造しない。

■6. 選ばなかった2箱のカードショップ販売（ユーザー正式方針）
登録イベントで受け取らなかった残り2種類は、導入イベント終了後、カードショップで少し高い価格で購入できるようにしてください。いずれも同じ正式箱画像を利用し、管理局受取と店頭販売で品目IDを共通管理できるようにする。ただし、初回の無料配布は別の取引として管理し、二重受取禁止。
・初回は3種の中から1種だけ無料で受け取り。未選択2種はショップで選択できる。
・具体的な販売価格・商品中身・排出率は、ユーザーからの確定値を参照すること。未確定なら価格を勝手に決めない。仮の商品レコード・表示枠だけ設置し、購入確定やコイン減算は正式価格・中身が確定するまで保留し、その旨を報告する。
・ショップ画面の既存カードパック販売機／ガチャ・商品表示を壊さない。今回の3種を既存仮パック（pack-01〜03）に自動的に上書きしない。必要なら別IDで管理し、既存データとの整合を示す。
・管理局で選んだ1種をショップにも並べるかどうかは指示されていないので、今回は「選ばなかった2種のみを購入候補」とする。一般販売の追加ルールを創作しない。

■7. 指アイコン
既存で使える指のUI素材があれば流用する。なければSVGまたはCSSによる暫定アイコンでよい（画像AIでの新規作画は不要）。幼馴染の会話と選択状態を常に同期させ、別箱へ変更したら指も一緒に移る。過剰なアニメーション・大きな絵文字は使用しない。

■8. 受入検査（必須）
1. 原画が参照ZIPに保存され、3つの個別PNGへ正しく切り出されている。3箱すべてで上面・側面・ロゴ・商品名が欠けず、キャラデザインに変更なし。
2. 3箱が同じ高さ・適切なタップ領域でiPhone縦画面に表示され、顔・ロゴ・名前が隠れない。
3. 初期状態は未選択、指なし。A初回→A説明・指・未配布。A2回目→Aを1回だけ確定。
4. A→Bの1回目では受取なし。A→B→BでBのみ確定。3種類すべてでテスト。
5. 連打・二重タップ・アプリ再開・戻る操作でも誤選択と二重受取が発生しない。
6. 初期デッキ3種のどれでも、管理局の3箱を独立して選べる。
7. 確定後は受付→退場→幼馴染の案内→自由行動へ正常につながる。
8. 選ばなかった2種類のショップ扱いは仕様どおり。価格未確定時の購入・コイン減算は動かさない。
9. 本件以外（戦闘、ガウルのカード表示、初期デッキ、町、教習所、管理局、既存ガチャなど）に回帰がない。
10. npm run typecheck / npm run test / npm run build を実施し、画面テストとiPhone相当の狭い縦画面スクリーンショットも提出。iPhone実機テストはユーザー自身の判定と区別する。
